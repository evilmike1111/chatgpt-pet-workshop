# 實作案例：玄龍 ZERO 的失敗與正確接續方式

> **案例狀態（2026-11-05）**：本案例是仍在進行中的製作紀錄，不是已建立、已安裝或已啟用的 Pets 成品。為了公開分享工作方法，**本 repo 不收錄 ZERO 的原始 PNG、壓縮包、私人路徑或寵物設定**。本頁只記錄流程與可驗證的檢查結果。

## 角色與需求

- 角色：玄龍 ZERO，黑金機械龍，四足、龍角、琥珀眼睛、能量紋路、翅膀與胸前晶核。
- 目標：沿用原本角色造型與九組動作，依 Pets v2 建立符合規格的 16 方向視線素材，最後經驗收才建立與啟用。
- 視線方向：**身體可以維持自然站姿、由眼睛／頭頸表達方向**；不要求整隻龍旋轉 360°。
- 公開原則：不把私人角色圖與未驗收修補版本直接提交教學 repo。

## 曾走過的路

| 階段 | 已證實的成果 | 尚未過關之處 |
| --- | --- | --- |
| v6 試作 | 有九組動作與 16 方向圖集，可產出預覽 | 方向採 2D 頭部重組、鏡像／局部修補，未符合完整正式建立與品質驗收 |
| v6.1 格式清理 | 原圖集全透明像素殘留 RGB **656→0**；前九列保持；本機結構驗證及 Pets 預檢回 `valid: true` | 16 方向逐格語意尚待人工驗收；格式成功**不是** Pets 建立成功 |
| P0-001 診斷 | 建立視覺比對、接縫／透明區域檢查、動畫預覽及規格檢查紀錄 | 未產生合格的新方向列；透明空隙不能一律當成破洞 |
| P0-002 早期試作 | 多次四方向候選產出，辨識出上右下左與版面要求 | 常出現身體跟著轉、假棋盤格、角色頭身比例漂移、單格要求被生成成四格；因此淘汰 |
| 官方生成流程準備 | 已由 `prepare_pet_run.py` 成功建立工作區，`ready_jobs` 僅有 `base`；`base` 任務仍 `pending` | 還**沒有**通過官方生成的 canonical base、四方向基準或兩組 8 格方向列 |

## 最新已核對的本機準備結果

使用者於本機對兩張原版參考圖片完成 Pillow 唯讀檢查：

| 用途 | 圖像尺寸 | 模式 |
| --- | --- | --- |
| 原始 ZERO 單格角色參考 | **192×208** | **RGBA** |
| 原版四方向參考 | **768×208** | **RGBA** |

`imagegen-jobs.json` 中的 `base.input_images` 已設定兩張參考圖，`output_path` 為 `decoded/base.png`，`status` 仍為 `pending`。這只代表**生成工作準備完成**，並非圖已生成或通過檢查。正式生成時還要依任務指定來源，實際附圖給 `$imagegen`。

當時 `imagegen-jobs.json` 的根層結構包含 `schema_version`、`created_at`、`run_dir`、`primary_generation_skill`、`jobs`；不要在不知道版本差異的情況下假設每個欄位都通用。

## 三個核心教訓

1. **定義先行：** Pets 16 個方向是「看向」不同方向；0°＝上、90°＝右、180°＝下、270°＝左。弄錯這個定義，漂亮的轉身圖也會失敗。
2. **生成來源大於修補技巧：** 文字描述或將四格放在圖上，不能確保模型保留原角色。要依正式工作相依性，確實附上 canonical base、身份參考與版面引導，生成**連貫的整組**影格。
3. **三重門檻：** 透明與尺寸正確 → 方向語意與動作品質正確 → Pets 真正建立並取得 ID。每一層都要有不同的證據。
