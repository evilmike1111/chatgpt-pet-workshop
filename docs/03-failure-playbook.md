# 失敗排除：為什麼圖看起來完成，卻不能建立 Pets？

本頁整理**真實製作過程中出現過的問題**。原則：先辨識是生成、提取、結構、語意或動態問題，再修最小失敗範圍；不要靠變更多個版本號掩蓋根因。

| 症狀 | 可能根因 | 建議處理 |
| --- | --- | --- |
| 生成了漂亮的「完成報告」或教學海報 | 圖像生成把規格、標籤、UI 一起畫進圖片 | 提示詞只描述角色與影格，禁止文字／介面／說明牌；報告用文字文件獨立製作 |
| 要 1 格卻輸出 4 格 | 模型偏好展示型 sprite sheet，沒有依既定工作依賴與輸入圖生成 | 回到官方 `imagegen-jobs.json` 的 job、輸入參考與 layout guide；不把錯誤輸出塞進單格 |
| 宣稱透明，實際為 RGB 或畫了棋盤格 | 生成器以棋盤格當視覺背景；或去背不完整 | 檢查實際編碼與 alpha，不用肉眼想像；依官方色鍵／去背流程處理 |
| 透明像素 RGB 不為零 | 色鍵清理或影像輸出留下不可見顏色 | 做非可見像素的 deterministic 清理，**重新驗證清理後的確切檔案**；此修補不代表視線合格 |
| 同一寵物越生成越像另一隻 | 沒有附原始 canonical 參考、細節太多、整組重新設計 | 先鎖定角色身份：頭身比例、臉型、瞳孔、角、胸晶、翼、腳位；拒絕身份漂移 |
| 四方向變成四個身體朝向 | 把 0°／180° 當正反面或把「look」解讀成 turntable | 0°＝向上、180°＝向下；先驗收四個基準，再做 8+8 方向 |
| 只降低接縫像素差異，畫面反而閃爍 | 光流、局部貼頭、鏡像拼接讓龍角／眼睛／頭頸產生重影 | 不把差異數值當品質結論；重新生成失敗的完整一致方向列 |
| 跳躍在程式上有影格，但看不出離地 | 擷取影格錯置、逐格縮放、原始來源動作不清楚 | 依官方流程保持共同比例與基準線，檢查至少一格真正離地 |
| Pets 回 `valid: true`，但品質仍未完成 | `valid` 是格式預檢，不是 16 方向語意或動態驗收 | 要求 `direction-semantics.json` 完整、`validate_pet_quality.py` 的 `ok: true` 及實際播放檢查 |
| 圖集已做，建立後 Pets 清單卻看不到 | 把驗證／上傳 session 當成穩定 pet ID | 建立後核對正式 ID，分頁查 `list_pets`；若要求啟用，核對 active pet ID |

## 不同類型錯誤的修復順序

1. **來源缺失：** 找回正確原圖、權利資訊與官方腳本，不先產生新版。
2. **格式／背景：** 修好色鍵、透明像素、尺寸及格位後，跑實際檔案驗證。
3. **動作問題：** 找出是哪個獨立動作列失敗，回到該列來源修正。
4. **方向語意：** 先處理四基準，再處理整段 8 格方向家族；禁止用一張獨立補頭圖繞過合規流程。
5. **無法驗證：** 標 `BLOCKED` 或 `REVIEW_REQUIRED`，保留證據與缺口，不寫成 PASS。

## 一個值得記住的反例

有一次方向動畫的 157.5°→180° 與 337.5°→0°，經 2D 鏡像與頭部重組，輪廓差異明顯降低；**但角色角度連續性、頭頸品質與製作方式仍未通過正式驗收**。這證明：

> 「像素差異改善」只能說明量測數字變小，**不能證明動畫自然、語意正確或流程合規**。

## 省額度策略

- 已存在且通過的素材不要反覆重生成。
- 一次釐清失敗類型，避免對同一張錯誤設計連續下近似提示詞。
- 先準備標準來源、layout guide 與生成任務相依性；只做已解鎖的 job。
- 缺少 `$imagegen` 或官方腳本時先停止，不能用合成宣傳圖或模型自製的「PASS」取代。
- 開發階段集中在私有工作目錄；**正式合格後才發布可公開的成品**。
