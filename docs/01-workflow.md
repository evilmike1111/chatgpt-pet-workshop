# 從角色概念到 ChatGPT Pets：製作流程

> 繁體中文實作指南｜以目前可用的 Pets v2 建立流程為例。功能、檔名與指令可能隨版本改變；**實際操作以你已安裝的 create-pet 技能與其共享規格為準**。本教學不是 OpenAI 官方文件。

## 先理解「完成」有四種不同意思

1. **素材存在**：已生成圖檔，不代表尺寸或角色一致。
2. **結構合格**：圖集、影格數、格式預檢通過，不代表動畫自然。
3. **視覺與流程合格**：官方品質檢查、方向語意、逐格與播放驗收都通過。
4. **實際建立成功**：Pets 建立回傳穩定寵物 ID，且清單與啟用狀態驗證成功。

沒有完成第 3 步，不應把素材標成「正式可上傳」；沒有第 4 步，不應聲稱「Pets 已啟用」。

## A. 準備來源與工作目錄

- 先確認自己的 Pets 功能、`create-pet/SKILL.md`、共享 sprite-sheet／preview 規格、附帶 `scripts/` 與 Python Pillow 是否可用。
- 保存角色名稱、外觀、個性、原始參考圖、授權與避開的元素。原始圖**只作身份參考**，不等於合規圖集。
- 使用一個工作目錄，分成 `source/`（唯讀）、`working/`、`rejected/`、`qa/`、`final/`。未通過驗收前不要覆蓋原檔，也不需要反覆把失敗版本上傳公開儲存庫。
- 路徑、個人資料、金鑰、私人素材與尚未取得發布權利的圖檔不要提交到公開 GitHub。

## B. 準備官方任務，而不是自己編造圖集規格

使用安裝的 `prepare_pet_run.py` 建立 `pet_request.json`、`imagegen-jobs.json`、版面引導圖與提示詞。範例（實際參數以安裝版本為準）：

```bash
python "$SKILL_DIR/scripts/prepare_pet_run.py" \
  --pet-name "你的寵物名稱" \
  --description "一句角色描述" \
  --pet-notes "必須保留的外觀與姿態" \
  --style-preset "pixel" \
  --output-dir "$RUN_DIR"
```

從 `imagegen-jobs.json` 查 `ready_jobs`、`depends_on`、`input_images`、`prompt_file`、`output_path`。如果只有 `base` 可執行，就**先處理 base**，不要跳到方向列。

**重要：** 把參考路徑寫進 JSON，不等於生成工具已收到圖片；實際生成呼叫仍要帶入 manifest 指定的來源及版面引導圖。產出檔案存在、通過必要檢查後，才能更新工作的完成狀態。

## C. 先建立 canonical base

先用官方要求的 `$imagegen` 產生單一、完整、容易縮到 192×208 辨識的角色基準姿態。對既有角色務必附上原版參考，讓頭身比例、眼睛、裝甲與材質不漂移。

若官方提示詞採單一純色 chroma-key 背景，請維持指定顏色；**不要畫棋盤格假裝透明**，也不要讓去背色出現在角色本身。拒收說明牌、圖文資訊圖、文字標籤、模糊光暈及裁切角色。

## D. 製作九個動作列

Pets v2 的前 **9 列（零起始索引 0–8）**是動作：`idle`、`running-right`、`running-left`、`waving`、`jumping`、`failed`、`waiting`、`running`（工作處理中）、`review`（完成／檢視）。

每個動作列獨立生成、獨立檢查，再用官方 `extract_strip_frames.py`、`inspect_frames.py` 等腳本提取與驗收。不能把等待、處理中、失敗等狀態單純複製別的動作冒充。

特別檢查：待機是否真的有微動、跑步步態是否交替、跳躍是否確實離地、完成動畫是否可辨。`running-left` 在規範允許、且不影響角色標記／打光／慣用邊時，可由核准的向右跑影格逐張鏡像；**這不等於方向視線列可以任意拼貼或鏡像**。

## E. 製作四基準＋16 個視線方向

後兩列是 **look row 9 與 row 10（零起始索引；人類口語即第 10、11 列）**，每列 8 格，共 16 方向，順時針每次 22.5°。

| 基準方向 | 真正意思 |
| --- | --- |
| 0° | 向上看，不是正面待機 |
| 90° | 向畫面右方看 |
| 180° | 向下看，不是背面 |
| 270° | 向畫面左方看 |

流程：用 `$imagegen` 先生成**同一組**四方向基準，抽取並檢查；通過後生成 0°～157.5° 的 **8 格連貫影格組**、完成對齊與檢查；再以核准基準和上一組結果生成 180°～337.5° 的第二組。最後檢查整圈，包括 157.5°→180°、337.5°→0°。

重點不是整隻寵物做 360° 轉台。眼睛、鼻尖、頭部、頸部、遮擋關係必須能表達看向哪裡，同時保留角色原有構造。若某個方向不對，應改善該**整組方向列**的生成，而不是用單張貼頭、扭曲、全身旋轉或任意拼接遮掩。

## F. 使用官方腳本做最後驗收

先後執行安裝版本要求的處理與驗證，包括：

- `despill_chroma_edges.py`：依官方流程處理指定 chroma key 並保留報告。
- `validate_atlas.py --require-v2`：檢查**將要交付的同一份檔案**，結果須 `ok: true`。
- `make_contact_sheet.py`、`make_direction_qa_sheet.py`、`measure_direction_continuity.py`：產出逐格／方向／銜接證據。
- `qa/direction-semantics.json`：16 方向都需寫明 `expected`、`observed`、`verdict`、具體可見特徵；不能自動填滿 PASS。
- `validate_pet_quality.py`：完整品質檢查須 `ok: true`，不能用單純尺寸檢查替代。
- `validate_pet_spritesheet`：Pets 的格式預檢須 `valid: true`。

同時檢查動作 GIF／影片、方向循環、待機→跳躍→待機、正常顯示尺寸與接縫，必要時找第二位不知角度標籤的審查者。任何一項必檢缺失、方向錯誤、不可辨識或產出檔位元組變動，都要重驗，不能沿用舊 PASS。

## G. 交付與建立

先展示**實際動態預覽**供確認。全部必要證據通過後，才能使用該版本的 Pets 上傳／建立流程；建立成功要記錄穩定 pet ID，若需要啟用，再驗證 active pet ID。格式 `valid: true` **不是建立成功**。

本工作坊以「**最後才上傳**」為預設範例：試作期資料留在私有工作區；只有明確合格且可公開的教學素材才放到本儲存庫。
