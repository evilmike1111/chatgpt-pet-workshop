# 04｜常見失敗

以下都是實際製作時遇到的狀況。

## 本機路線的坑（玄龍實測）

### 給模型兩張參考圖，結果變成四宮格
把「角色」和「四方向參考圖」一起給 Qwen，模型會照第二張的版面畫出四宮格。改成只給一張（idle 單格貼在洋紅底上），並在負面提示寫 `multiple views, grid, collage`。

### FLUX.3 Klein：角色像，但不會轉頭
四個方位出來都是正面看鏡頭；背景是偏粉的洋紅，不是 `#FF00FF`，去背困難。改用 Qwen-Image-2.1 後，背景是純洋紅，方向也有反應。

### 往下看（180）那格身體縮小
多數 seed 的 180 會把整隻龍畫小，而且位置往上飄 24 到 67 像素。換提示詞（改成「低頭，下巴靠近胸口，頭頂和角朝向觀看者」並要求身體大小位置不變）再換 seed，才得到身體大小正常的結果。**用數字挑圖**：量腳底帶寬度與基準線，跟輸入圖比較，比肉眼可靠。

### 每格加大到跟 idle 一樣大，頭角被切掉
Qwen 生出的頭比 idle 的頭大，直接放進 192 寬的格子，頭角會貼到邊或被切。腳本 03 先把整張 1024 畫布依 idle 的位置對齊，再整體縮到 93%，最後才裁成格子。

### 驗證腳本沒有報洋紅殘邊
`validate_atlas.py` 預設色鍵是綠色 `#00FF00`。洋紅底的圖要加 `--chroma-key "#FF00FF"`。

### WebP 存檔後驗證失敗
無損 WebP 預設會改動完全透明像素的 RGB，驗證會報「透明像素殘留 RGB」。存檔時加 `exact=True`。

### 腳本沒錯誤卻沒有更新結果
這次發現兩次：一次是腳本其實有語法錯誤，但輸出被我丟掉，看到的是上一版的檔案。**每次重跑都看輸出，並比對輸出檔的 SHA-256 有沒有變。**

## 付費路線（Codex）的坑
### 本機模型（例如 ComfyUI＋FLUX）生的圖拿來用

本機推論可以成功，但角色會被「重新設計」：角變大、頭身比例改變、裝甲與翅膀細節不同，背景也不是透明的。即使給多張參考圖也鎖不住身份。官方合約要求寵物影像由 `$imagegen` 生成，所以本機生圖只適合用來發想，不要放進正式圖集。

### 用鏡像或拼接補方向格

把頭部拼到身體上，或把左半邊鏡像成右半邊，結構驗證可能會過，但轉頭時輪廓會跳、翅膀左右不一致，而且違反合約。正確做法是整列重生。

### 結構檢查 PASS 就以為完成

格數、尺寸、透明度都對，不代表動作是對的。jumping 變成角色縮放、方向轉反，都只能靠看預覽發現。

### 任務單把生圖輸出位置也禁止了

`$imagegen` 內建工具會先把圖存在 Codex 自己的資料夾（`$CODEX_HOME/generated_images`），再由 Codex 複製到你的專案。如果任務單寫「不准改動 Codex 所在磁碟的任何檔案」，Codex 會因為不能存圖而停下，一張都不生。限制應該寫成「不准改動原始素材」，不要整個磁碟一起禁止。

### 生圖工具不可用時改用其他方式硬做

合約規定生圖不可用時要停在上傳前，不能用程式畫、SVG 或其他工具補一張假圖。
